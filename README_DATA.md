# README_DATA

## Формат словаря микрокатегорий
Файл: `data/microcategories.json`

Каждый объект:

```json
{
  "mcId": 101,
  "mcTitle": "Сантехника",
  "keyPhrases": ["сантехника", "разводка труб"]
}
```

Поля:
- `mcId`: уникальный id микрокатегории
- `mcTitle`: название
- `keyPhrases`: список фраз-индикаторов

## Формат входного объявления
Файл: `data/input_item.json`

```json
{
  "itemId": 9001,
  "mcId": 201,
  "mcTitle": "Ремонт квартир и домов под ключ",
  "description": "..."
}
```

Важно:
- `mcId` и `mcTitle` здесь означают исходную микрокатегорию уже существующего объявления;
- эта категория может быть обнаружена в тексте, но не должна повторно попадать в список дополнительных draft-категорий.

## Формат примеров для оценки
Файл: `data/examples.jsonl`

Каждая строка содержит:
- поля объявления;
- `shouldSplit`;
- `expectedDraftMcIds`.

Пример:

```json
{
  "itemId": 5002,
  "mcId": 201,
  "mcTitle": "Ремонт квартир и домов под ключ",
  "description": "Выполняем электрику отдельно, сантехнику отдельно, а также ремонт под ключ.",
  "shouldSplit": true,
  "expectedDraftMcIds": [101, 102]
}
```

## Рекомендации по данным
- В `keyPhrases` полезно хранить и короткие, и длинные варианты.
- Полезно добавлять синонимические и морфологические варианты, особенно для русских сервисных формулировок.
- Для ambiguous кейсов лучше иметь отдельную разметку и причины отказа.
- Если есть табличные данные, их лучше конвертировать в JSONL перед оценкой.
